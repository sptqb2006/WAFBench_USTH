[FILE 1] WAFBench_USTH/telemetry/schema.sql
------------------------------------------------------------------------------
Purpose:
  Defines the relational data architecture in PostgreSQL 16 to persist 
  cross-tier telemetry records and aggregated benchmark metrics.

Key Changes & Rationale:
  1. Conformance to Table 4.3 (Normalized Events):
     - correlation_id VARCHAR(64) UNIQUE NOT NULL:
       Set as UNIQUE to enable atomic UPSERT (ON CONFLICT DO UPDATE) operations.
       This prevents race conditions between the test runner probe capture and 
       the asynchronous WAF audit log ingestion.
     - client_ip VARCHAR(45):
       Added to store the originating IP of the client runner.
     - waf_payload_snippet TEXT:
       Added to capture the exact offending payload substring from 
       ModSecurity messages (messages[].details.data). This field is strictly 
       required for the Forensic Inspection Drawer (Block B) in the dashboard.
     - waf_matched_variable TEXT:
       Added to capture the targeted input variable (e.g., ARGS:username) from 
       messages[].details.variable.
     - root_rule_id INT & root_rule_name TEXT:
       Added to record the primary CRS rule ID (e.g., 942100) and its 
       descriptive label alongside the full matched_rule_ids JSONB array.
     - raw_log_ref TEXT:
       Added to hold the SHA-256 fingerprint / pointer back to the raw line in 
       /var/log/modsec/audit.log for forensic auditability.
     - oracle_observation TEXT:
       Preserves backend evidence findings (e.g., unauthorized session issued, 
       file contents leaked) reported by Express target application oracles.

  2. Conformance to Table 4.6 (Evaluation Metrics):
     - Pre-filtering sample accounting columns:
       total_attempted, total_evaluable, total_invalid, total_inconclusive.
     - Quantitative evaluation KPI columns:
       detection_rate (DR), blocking_rate (BR), detection_fpr (Detection FPR),
       blocking_fpr (Blocking FPR), and regression_pass_rate (RPR).

  3. Query Optimization & Indexing:
     - CREATE UNIQUE INDEX idx_events_correlation_id ON normalized_events(correlation_id);
     - CREATE INDEX idx_events_batch_id ON normalized_events(batch_id);
     - CREATE INDEX idx_events_run_id ON normalized_events(run_id);
     - CREATE INDEX idx_events_case_id ON normalized_events(case_id);
     - CREATE INDEX idx_events_state ON normalized_events(state);
     - CREATE INDEX idx_events_verdict ON normalized_events(verdict);
     - CREATE INDEX idx_events_metric_cell ON normalized_events(metric_cell);
     * Rationale: High-throughput ingestion by worker daemons and real-time 
       filtering in the Streamlit dashboard require sub-millisecond lookups on 
       correlation keys, execution states, and evaluation verdicts.


[FILE 2] WAFBench_USTH/telemetry/db.py
------------------------------------------------------------------------------
Purpose:
  Serves as the database connection manager, schema deployment orchestrator, 
  and data access layer (DAL) for telemetry worker daemons and the test harness.

Key Changes & Rationale:
  1. Resilient Driver Import:
     - Wrapped psycopg2 and RealDictCursor inside a try-except block.
     - If run on a host machine without psycopg2 installed, it does not crash,
       allowing schema viewing and local terminal demonstrations to function.
     - Inside Docker containers, psycopg2 is natively available via requirements.txt.

  2. Configuration & Connection Helpers:
     - get_db_config(): Reads environment variables (EVENT_DB_HOST, EVENT_DB_PORT, 
       EVENT_DB_NAME, EVENT_DB_USER, EVENT_DB_PASSWORD) with safe defaults.
     - get_connection(): Returns a PostgreSQL connection with RealDictCursor.
     - test_connection(): Non-throwing probe returning boolean connection health.

  3. Automated Schema Initializer:
     - init_db(schema_path=None): Reads and executes schema.sql against PostgreSQL,
       allowing one-command table provisioning and migrations.

  4. Data Pipeline Methods:
     - upsert_client_event(record):
       Uses SQL ON CONFLICT (correlation_id) DO UPDATE. Guarantees that whether 
       the client probe or WAF log arrives first, the record is safely ingested 
       without duplicate key exceptions or lost data.
     - update_waf_telemetry(correlation_id, waf_data):
       Enables worker.py to update WAF-specific audit fields (matched rules, 
       anomaly score, disruptive action, payload snippet, raw log ref).
     - update_verdict(correlation_id, verdict_data):
       Enables correlation.py to commit final verdict (PASS/FAIL) and metric cell 
       (TP_B, FN_B, FP_D, etc.).
     - get_recent_events(limit=20):
       Helper function returning recent rows for dashboard and CLI views.

  5. Built-in Terminal CLI & Viewers:
     - Added print_schema_overview() triggered by '--schema':
       Prints a clean ASCII specification table of both Table 4.3 and Table 4.6.
     - Added run_local_terminal_demo() triggered by '--demo':
       Uses Python's built-in sqlite3 engine to simulate the entire 3-tier 
       lifecycle in memory (Client probe -> WAF log update -> Oracle correlation ->
       Querying final record). Provides immediate visual proof in the terminal 
       without needing Docker or PostgreSQL running.
